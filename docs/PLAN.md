# 再生医療ガイド：全体計画（初期案）

作成日：2026年9月19日。サイト名は仮称です。以下の期間・記事数は企画上の目安で、検索順位・集客・収益を保証するものではありません。

## 1. サイトの目的と読者

再生医療・幹細胞について知りたい一般の方に、用語、研究の位置づけ、治療を検討する際の確認事項を伝える専門メディアを作ります。読者が出典をたどり、医師に相談するときの疑問を整理できることを重視します。

Googleは、健康に影響を与える分野で信頼性を重視する方針を説明しています。医師名を載せるだけでなく、監修の実態・根拠・利益相反・更新履歴を示す運用を目指します。E-E-A-Tそのものが単独のランキング要因という意味ではなく、監修を付けても順位は保証されません。[Googleのコンテンツ品質に関する案内](https://developers.google.com/search/docs/fundamentals/creating-helpful-content)

## 3. 検索流入を育てる方針

### 初期コンテンツ案

最初の目標を10〜15本の監修済み記事とし、検索意図が重なる小さな記事の量産を避けます。検索数は未調査のため、以下は検索需要を保証するキーワードではありません。公開前に検索結果の傾向と読者の質問を調査して優先度を修正します。

| 優先度 | 中心となる記事             | 関連する疑問・記事候補                           |
| ------ | -------------------------- | ------------------------------------------------ |
| 高     | 再生医療とは               | 対象分野、研究段階、既存の医療との関係           |
| 高     | 幹細胞とは                 | iPS・ES・体性幹細胞の違い、分化と自己複製        |
| 高     | 治療を検討する前の確認事項 | 効果の根拠、リスク、代替治療、相談方法           |
| 高     | 費用の確認方法             | 検査・採取・投与・通院を含む総額、保険の扱い     |
| 中     | 研究ニュースの読み方       | 細胞実験・動物実験・臨床研究、人数・比較・限界   |
| 中     | 制度と承認の読み方         | 提供計画と承認の区別など、最新制度を専門家と確認 |
| 中     | 医師に聞く質問集           | 診療時に使える確認リスト、説明と同意             |

一般論と特定の治療・製品の承認状況を混ぜず、費用や有効性を治療名なしで一括りにしません。公的な届出等を効果の保証と受け取らせる表現を避けます。

### 技術面

- Next.jsの静的書き出しにより各URLで本文を含むHTMLを配信。本文をJavaScript実行後にだけ表示する構成にしない。
- ページ別のtitle、description、canonical、OGP、パンくずを設定。
- `WebSite`、`BreadcrumbList`、監修・公開条件を満たす記事の`Article`構造化データを用意。表示内容と一致させる。特別な検索表示を保証しない。
- 安定した英語slug、カテゴリ・関連記事の内部リンク、HTTP 404、サイトマップを整備。
- フォントの外部読み込みを避け、ヒーローはSVGで軽量化。画像・広告はサイズを予約してレイアウト移動を抑える。
- 公開後にSearch Consoleで登録状況・検索語・表示回数・クリック率を確認。Core Web Vitalsは実測し、改善箇所を判断。
- 準備中は全ページnoindex。未監修のサンプル記事は公開設定を変更してもnoindex・サイトマップ除外を維持。

[Google Search Essentials](https://developers.google.com/search/docs/essentials)に沿って、読者に役立つ本文・分かりやすいタイトル・巡回可能なリンクを整備します。

## 4. 編集・監修のワークフロー

1. 読者の疑問、記事の対象範囲、検索意図を定める。
2. 公的機関・学会・原著論文などを確認し、主張と根拠の対応を記録する。
3. 編集部が執筆。確立した事項、研究段階、不明な事項を区別する。
4. 対象領域の医師が医学的記述とリスク・効果の表現を確認する。
5. 所属・資格・氏名の掲載許諾、利益相反、監修範囲を記録する。
6. 反映確認後、公開日・監修日を設定して公開する。
7. 読者からの指摘や知見の変化を受けて修正し、重要な改訂を記録する。

基礎記事は半年ごとを再確認の目安とし、制度・承認・治療情報は変化を把握した時点で再確認します。監修契約に更新時の担当範囲を含めます。これらは今後構築する運用であり、現在の監修実績ではありません。

## 5. 広告による収益化

最初は直接契約の静的バナーを想定します。広告主、掲載位置、期間、素材、リンク先、料金、審査記録、利益相反を管理します。料金は実際のアクセス規模・閲覧者層が分かった後に決め、PVや治療予約数を架空に表示しません。

| 掲載位置       | 素材の目安                             | 初期の運用案                   |
| -------------- | -------------------------------------- | ------------------------------ |
| トップ記事下   | 横長素材（例：728×90）とモバイル用素材 | 月単位の固定枠                 |
| 記事サイドバー | 例：300×250                            | 関連カテゴリ単位の固定枠       |
| 記事本文下     | 横長または300×250                      | 読了後に案内、内容と広告を区別 |

サイズは入稿規定作成時に最終決定します。広告主の要望で医学的結論を書き換えないこと、PR表記、`rel="sponsored noopener noreferrer"`を前提にします。雛形では広告配信・クリック計測を開始していません。

医療広告の適用範囲や掲載可能な表現は、媒体・誘引性・内容・リンク先などによって個別の確認が必要です。実際の掲載前に最新版の[厚生労働省の医療広告規制資料](https://www.mhlw.go.jp/stf/seisakunitsuite/bunya/kenkou_iryou/iryou/kokokukisei/)を確認し、必要な専門家レビューを行います。免責文だけで広告の問題が解消するという扱いにはしません。

## 6. 技術・運用構成

```text
記事・監修情報（現状：TypeScriptのデータ）
           ↓ 編集・医師確認
Next.jsでローカルまたはCIビルド
           ↓ out/ に静的ファイルを生成
FTPSでレンタルサーバーの公開フォルダへ
           ↓
読者へHTML・CSS・JS・画像を配信
```

ホスティング側にNode.jsやデータベースは不要です。検索はブラウザ内で実行し、問い合わせは受付先設定後のメールリンクです。問い合わせフォーム、広告計測、CMS、予約機能は別途設計が必要です。

記事が増えたらMarkdown/MDXやヘッドレスCMSへの移行を検討します。CMSを使う場合もビルド時に取得し、公開成果物は静的ファイルを維持できます。記事更新には再ビルド・再アップロードが必要です。大規模化した場合は検索用インデックスを分離し、全文をクライアントへ渡す現在の検索を見直します。
